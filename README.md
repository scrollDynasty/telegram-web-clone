# Telegram Web · GREEN-API

Веб-чат для отправки и получения текстовых сообщений **Telegram** через [GREEN-API](https://green-api.com/telegram/).
Интерфейс сделан по мотивам web-клиентов мессенджеров (Telegram Web / web.max.ru): двухпанельный layout, пузыри сообщений, светлая и тёмная темы, адаптив под телефон.

**Демо:** https://scrolldynasty.github.io/telegram-web-clone/

## Возможности

- Вход по `idInstance` и `apiTokenInstance`. `apiUrl` необязателен: по умолчанию он вычисляется из `idInstance` (`https://4100.api.green-api.com` для `4100…`). Перед входом проверяется, что инстанс авторизован.
- Новый чат по номеру телефона (или `@username`). Номер заранее превращается в Telegram `chatId` через `CheckAccount`.
- Отправка текстовых сообщений методом [`SendMessage`](https://green-api.com/telegram/docs/api/sending/SendMessage/): оптимистичный UI, статусы ⏳ → ✓ → ✓✓ и повтор при ошибке.
- Получение сообщений через [HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/) (`ReceiveNotification` + `DeleteNotification`, long polling).
- Сообщения, отправленные с телефона, тоже появляются в чате. Приходят статусы доставки и прочтения.
- Список чатов с поиском, превью последнего сообщения и счётчиком непрочитанных. Непрочитанные видны и в заголовке вкладки.
- История хранится локально, отдельно для каждого инстанса. Есть опция «Запомнить на этом устройстве».
- Светлая, тёмная и системная тема. Мобильная вёрстка. Доступность: клавиатура, `aria-live`, фокус, `prefers-reduced-motion`.

## Быстрый старт

Требуется Node.js ≥ 20.19 (см. `.nvmrc`).

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173 и введите данные инстанса.

### Подготовка инстанса GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com) и создайте инстанс **Telegram**.
2. Авторизуйте его: Telegram → Настройки → Устройства → Подключить устройство → отсканируйте QR.
3. На странице инстанса скопируйте `idInstance` и `apiTokenInstance` (и `apiUrl`, если он отличается от `https://<первые 4 цифры idInstance>.api.green-api.com`).
4. В настройках инстанса:
   - поле **URL для уведомлений (webhook)** должно быть пустым, иначе HTTP API не отдаёт уведомления;
   - включите «Получать уведомления о входящих сообщениях»;
   - по желанию: уведомления об отправленных с телефона сообщениях и о статусах исходящих.

## Архитектура

Облегчённый Feature-Sliced Design:

```
src/
├── shared/            # переиспользуемое, без бизнес-логики
│   ├── api/           # GreenApiClient (fetch + zod), ошибки, React-контекст клиента
│   ├── lib/           # телефоны, даты, инициалы
│   └── ui/            # Button, TextField, Dialog, Avatar, IconButton, Linkify…
├── entities/          # доменные модели и состояние
│   ├── chat/          # модель чата/сообщения, zustand-стор (persist), статус-иконки
│   ├── notification/  # parseNotification: сырой webhook → доменное событие
│   ├── session/       # учётные данные и аккаунт
│   └── theme/
├── features/          # пользовательские действия
│   ├── auth/          # форма входа
│   ├── new-chat/      # диалог нового чата (CheckAccount)
│   ├── send-message/  # оптимистичная отправка и повтор
│   ├── polling/       # цикл receive → handle → delete с backoff
│   └── theme/
├── widgets/           # крупные блоки UI: sidebar, chat (лента, пузыри, composer)
└── pages/             # LoginPage, MessengerPage
```

### Ключевые решения

- **Без своего бэкенда.** По ТЗ пользователь вводит ключи в браузере, и браузер ходит в GREEN-API напрямую. Ключи хранятся только в `localStorage` или `sessionStorage` этого браузера.
- **`chatId` вместо `phone@c.us`.** В Telegram отправка по номеру без прошлой переписки падает с ошибкой `chatId unresolvable`. Поэтому при создании чата номер сразу превращается в `chatId` через `CheckAccount`, как рекомендует документация. Если у номера нет Telegram, об этом сообщается сразу, до первой отправки.
- **Надёжный polling.** Работает ровно один цикл (`AbortController`, корректно и в React StrictMode). Каждое уведомление удаляется из очереди, даже если оно не нужно или обработчик упал, иначе очередь «застрянет». Сетевые ошибки обрабатываются экспоненциальным backoff с jitter. Если GREEN-API отвечает, но не обслуживает инстанс (не авторизован, запускается, подписка истекла), в списке чатов показывается причина, а не «Ожидание сети». Отозванный токен выкидывает на экран входа с объяснением.
- **Несколько вкладок.** Очередь уведомлений опрашивает только одна вкладка (Web Locks API), остальные синхронизируются с ней через событие `storage` и подхватывают опрос, когда она закрывается.
- **Идемпотентность.** Повторная доставка уведомления и эхо `outgoingAPIMessageReceived` от собственного сообщения не создают дублей: сообщения сверяются по `idMessage`. Если уведомление пришло раньше ответа `SendMessage`, после таймаута или после перезагрузки вкладки, оно «усыновляет» локальную копию с тем же текстом. Статус, пришедший раньше `idMessage`, применяется, как только id становится известен.
- **Порядок сообщений.** Время уведомлений округлено до секунды и идёт по часам сервера, а свои сообщения — по локальным. Живые события в пределах 2 секунд от последнего сообщения ставятся в конец, поэтому ответ не «прыгает» выше вопроса.
- **Валидация на границе.** Все ответы API проходят через zod-схемы, некорректные данные не попадают в стор.
- **Статусы только вперёд.** Поздний `delivered` не перетирает `read`; `failed` и `noAccount` показываются с понятным текстом.
- **Безопасность.** Текст сообщений выводится как текст, без `dangerouslySetInnerHTML`. Ссылки открываются с `rel="noopener noreferrer"`.

## Деплой

Workflow `.github/workflows/ci.yml` на каждый push и PR запускает типы, линт, форматирование, тесты и сборку. При push в `main` сборка публикуется на **GitHub Pages**. Для этого в настройках репозитория выберите _Settings → Pages → Source: GitHub Actions_.

## Ограничения

- Только текстовые сообщения и личные чаты (группы и медиа вне рамок задания).
- История не подтягивается с сервера: чат показывает сообщения, полученные с момента входа.
- Если `localStorage` переполнен или отключён, чат продолжает работать, но история не сохранится после перезагрузки.

### Доступность: осознанные исключения

Цвета взяты из Telegram Web A. Текст, который несёт информацию (подписи полей, подсказки, ссылки, текстовые кнопки, счётчик символов), приведён к контрасту WCAG AA 4.5:1 отдельными токенами `--text-secondary` и `--accent-text`. Фирменные заливки оставлены как в Telegram, хотя крупный белый текст на них даёт меньше 4.5:1: кнопка «Войти» на `#3390ec`, зелёный счётчик непрочитанных, время в исходящих пузырях светлой темы, плашки дат на обоях, плейсхолдеры «Поиск» и «Сообщение».
